Bienvenida. Todo programa usa nombres para guardar cosas (variables, funciones). Esos nombres siguen reglas. Hoy escribimos un programa que revisa si un nombre cumple las reglas, y lo conectamos con la expresión regular y con un autómata.
I · El problema

Ponerle nombre a las cajitas

En un programa guardamos cosas en «cajitas» (variables) y cada cajita necesita un nombre. Pero no cualquier nombre vale.

La primera debe ser una letra inglesa: A–Z o a–z.
Después: letras, dígitos 0–9 o guion bajo «_», cuantos quieras (o ninguno).
Nada de espacios, guiones medios ni otros símbolos.
Lo revisamos todo el nombre, no solo una parte.
Un nombre vacío no es un nombre.
Lo que hay que programar
Una función es_identificador(cadena) que regrese True si la cadena es válida y False si no.
Como un club con reglas de entrada: el primero de la fila tiene que ser una letra; los demás pueden ser letras, números o guion bajo; y si cualquiera de la fila no cumple, no entra nadie.

I · El problema · La restricción

Prohibido usar expresiones regulares

No se vale

import re
ni Pattern (Java), <regex> (C++) u otras bibliotecas: sería dejar que otro haga el trabajo.

Sí se vale

Ciclos, condicionales y funciones que revisan cada carácter, uno por uno.
La idea
Vamos a entender cómo funciona por dentro una expresión regular: primero la leemos pieza por pieza, después la convertimos en un autómata y al final en código.
Una expresión regular es una receta; un programa con ciclos y condicionales es una forma de cocinarla a mano. Eso es justo lo que hacen las bibliotecas por dentro.
II · Entender la expresión

Leamos la expresión pieza por pieza

^aquí empieza la cadena
[A-Za-z]un carácter: una letra mayúscula o minúscula
[A-Za-z0-9_]*letras, dígitos o «_», cero o más veces (eso dice el *)
$aquí termina la cadena
Los corchetes […] significan «uno de estos caracteres» y A-Z es un rango: de la A a la Z. Juntas, las piezas dicen: «una letra, y después letras, dígitos o guiones bajos, hasta el final».
Esta es la notación de las bibliotecas de programación, distinta de la notación formal de la clase de expresiones regulares (allí escribiríamos la unión con +). La idea es la misma: un primer carácter fijo y una repetición.

Cuatro tipos de caracteres

Así se traduce la expresión
[A-Za-z] = «es letra» · [A-Za-z0-9_] = «es letra, dígito o guion bajo». Cualquier carácter de la clase otro hace que la cadena sea inválida.
Pregunta: ¿en qué grupo cae el espacio? ¿Y la ñ? Ambos son "otro". Que la ñ no cuente es importante en español: el enunciado pide letras inglesas.
II · Entender la expresión · La cadena completa

^ y $: no basta con una parte

abc␠def
«abc» sería válido, pero la cadena completa tiene un espacio: inválida.
2x
«x» sería válido, pero el primer carácter es un 2: inválida.
Las anclas
^ obliga a revisar desde el primer carácter y $ hasta el último. Sin ellas, la expresión aceptaría cadenas que solo contienen un pedazo válido.
En nuestro programa, "desde el primero" es revisar cadena[0], y "hasta el último" es que el ciclo recorra la cadena completa sin detenerse antes.
III · El autómata

La misma regla como una máquina de 3 estados

\(q_0\)
Inicio
aún no leemos nada
\(q_1\)
Válido (aceptación)
empezó con letra y todo ha estado bien
\(q_e\)
Error (trampa)
algo salió mal: de aquí ya no se sale
La máquina no lee caracteres sueltos sino su tipo: letra, dígito, «_» u otro.
q0 → q1 con letra es la pieza [A-Za-z]; el lazo de q1 es [A-Za-z0-9_]*; y q1 es de aceptación porque al llegar al final ($) todo cumplió.
III · El autómata · Definición

Tabla de transición y definición formal

Tabla δ

L = letra · D = dígito · O = otro · → inicial · * aceptación
\(M=(Q,\Sigma,\delta,q_0,F)\)
\(Q\)estados\(\{q_0,q_1,q_e\}\) \(\Sigma\)tipos de carácter\(\{L,D,\_,O\}\) \(q_0\)inicial\(q_0\) \(F\)aceptación\(\{q_1\}\)
Es un AFD completo: 3 estados × 4 tipos = 12 flechas. Una vez en \(q_e\) todas las flechas regresan a \(q_e\): por eso el programa puede responder False en cuanto encuentra el primer error.
El alfabeto de la máquina son los 4 tipos de carácter, no los caracteres: así 26 + 26 letras se convierten en un solo símbolo L.

Debajo de cada carácter aparece su tipo. La primera letra lleva de q0 a q1; después todo es letra, «_» o dígito, así que nos quedamos en q1 hasta el final.
III · El autómata · Simulación

Revisemos «mi-var»: el guion medio

Al leer el guion (tipo "otro") la máquina cae en el estado de error y ya no sale aunque lo demás sean letras. El programa en Python hace lo mismo con un "return False" en cuanto lo encuentra.

IV · Python · Funciones auxiliares

Primero: ¿es letra? ¿es dígito?

  identificador.py líneas 10–17
def es_letra(c):
    """Letra inglesa A-Z o a-z (no acepta ñ, á ni otras letras)."""
    return "A" <= c <= "Z" or "a" <= c <= "z"


def es_digito(c):
    """Dígito 0-9 (no acepta otros dígitos de Unicode, como ² o ٣)."""
    return "0" <= c <= "9"
Comparar rangos
Los caracteres tienen un orden (su código). "A" <= c <= "Z" pregunta «¿c está entre la A y la Z?». Es exactamente el rango [A-Z] de la expresión.
¿Por qué no usar…?Resultado en Python
'ñ'.isalpha()True pero «ñ» no es inglesa
'²'.isdigit()True pero «²» no es 0–9
es_letra('ñ')False como pide el enunciado
isalpha e isdigit entienden todos los idiomas de Unicode, lo cual normalmente es bueno, pero aquí el enunciado pide solo el alfabeto inglés y los dígitos 0 a 9. Los valores de esta tabla los comprueba el verificador ejecutando Python.
IV · Python · La función principal

es_identificador(cadena), línea por línea

  identificador.py líneas 20–29
def es_identificador(cadena):
    """Regresa True si la cadena es un identificador válido y False si no."""
    if not isinstance(cadena, str) or cadena == "":
        return False
    if not es_letra(cadena[0]):  # [A-Za-z]
        return False
    for c in cadena[1:]:  # [A-Za-z0-9_]*
        if not (es_letra(c) or es_digito(c) or c == "_"):
            return False
    return True  # se revisó hasta el último carácter: $
Si no es texto o está vacía: False (regla 5).
El primero debe ser letra: [A-Za-z] (regla 1).
Recorremos todos los demás: [A-Za-z0-9_]*.
Un carácter prohibido: False (reglas 2 y 3).
Llegamos al final sin errores: True. Eso es el $ (regla 4).
cadena[1:] es "la cadena sin su primer carácter"; si la cadena tiene un solo carácter, queda vacía y el ciclo no se ejecuta: "x" es válido (cero repeticiones del *).

V · Casos límite · Una trampa real

La trampa del $ en Python

  test_identificador.py
    def test_salto_de_linea_al_final(self):
        self.assertFalse(es_identificador("abc\n"))
        self.assertIsNotNone(re.match(r"^[A-Za-z][A-Za-z0-9_]*$", "abc\n"))  # la trampa del «$»
La sorpresa
En Python, $ también acepta un salto de línea al final. Con re.match, la expresión de referencia ¡acepta "abc\n"!
Nuestro programa
Revisa todos los caracteres, incluido \n (tipo «otro»): regresa False. Para comparar en las pruebas usamos fullmatch, que exige la cadena completa.
Detalle verificado en Python 3.12. Moraleja: escribir la regla a mano nos obliga a pensar en cada carácter, y evita sorpresas como esta. La prueba deja documentado el comportamiento de re.match.

# Se usa fullmatch: con re.match y «$», Python aceptaría "abc\n".
REFERENCIA = re.compile(r"[A-Za-z][A-Za-z0-9_]*")
  test_identificador.py
    def test_todas_las_cadenas_cortas(self):
        caracteres = "aZm09_- .ñ²\n$"
        revisadas = 0
        for n in range(5):
            for tupla in itertools.product(caracteres, repeat=n):
                cadena = "".join(tupla)
                esperado = REFERENCIA.fullmatch(cadena) is not None
                self.assertEqual(es_identificador(cadena), esperado, repr(cadena))
                revisadas += 1
        self.assertEqual(revisadas, sum(len(caracteres) ** n for n in range(5)))
13 caracteres de prueba (de todos los tipos), cadenas de longitud 0 a 4: \(1+13+13^2+13^3+13^4=30\,941\) comparaciones. La biblioteca re solo aparece aquí, como respuesta del maestro; identificador.py no la usa.
Es la prueba que confirma que nuestro algoritmo y la expresión regular dicen lo mismo. No es una demostración para todas las cadenas, pero cubre todas las combinaciones cortas de cada tipo de carácter.

def error_isalpha(cadena):
    """Usa isalpha/isalnum: acepta letras y dígitos que no son ingleses."""
    return cadena[:1].isalpha() and all(c.isalnum() or c == "_" for c in cadena)


def error_solo_primero(cadena):
    """Solo revisa el primer carácter: olvida el resto de la cadena."""
    return cadena != "" and ("A" <= cadena[0] <= "Z" or "a" <= cadena[0] <= "z")


def error_alguna_parte(cadena):
    """Acepta si ALGÚN carácter es letra: no exige la cadena completa."""
    for c in cadena:
        if "A" <= c <= "Z" or "a" <= c <= "z":
            return True
    return False
