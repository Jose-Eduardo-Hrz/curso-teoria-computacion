I · El problema

El juego de las tarjetas

Te paso tarjetas con 0 o 1, una por una. Tienes que gritar «¡la encontré!» si en algún momento ves 1, 0, 1 seguidas.

Σ
Solo hay dos tipos de tarjeta
el alfabeto es Σ = {0, 1}
Tienen que ir juntas
1, 0, 1 consecutivas, en cualquier lugar
Una vez encontrada, ya ganaste
las tarjetas que siguen no cambian nada
Una tarjeta rara lo arruina todo
si aparece un 2 o una letra: se rechaza
Lo que hay que programar
Una función acepta(cadena) que regrese True si la cadena contiene 101 y False si no, usando un autómata finito determinista.
Juega con el grupo: dicta 1, 1, 0, 1 lentamente y pide que griten cuando la encuentren. Pregunta: ¿qué tenías que recordar mientras escuchabas? Solo "cuánto de 101 llevo". Esa es la idea del autómata.

I · El problema · La regla especial

Prohibido hacer trampa

No se vale

"101" in cadena
ni find, index, contains, indexOf… Sería pedirle la respuesta a Python.

Sí se vale

Una máquina que lee una tarjeta a la vez y cambia de estado según una tabla de reglas.
¿Por qué así?
Porque el ejercicio es practicar autómatas: la máquina no puede «mirar toda la cadena»; solo puede recordar lo indispensable con un número finito de estados.
Esto también es como funcionan muchos programas reales que reciben datos poco a poco (por la red, por el teclado): no pueden esperar a tener toda la cadena.

Cuatro estados bastan, sin importar lo larga que sea la cadena: \(Q=\{q_0,q_1,q_2,q_3\}\), inicial \(q_0\), aceptación \(F=\{q_3\}\).

II · Diseñar el autómata · Definición formal

La definición matemática

\(M=(Q,\Sigma,\delta,q_0,F)\)
\(Q\)estados\(\{q_0,q_1,q_2,q_3\}\) \(\Sigma\)alfabeto\(\{0,1\}\) \(\delta\)\(\delta:Q\times\Sigma\rightarrow Q\)la tabla de la diapositiva anterior \(q_0\)estado inicial\(q_0\) \(F\)estados de aceptación\(\{q_3\}\)
Una cadena \(w\) se acepta si, después de leerla completa, la máquina termina en \(F\): \(\delta^*(q_0,w)=q_3\).
Es determinista porque de cada estado sale exactamente una flecha por símbolo: 4 estados × 2 símbolos = 8 transiciones.

IV · La solución en Python · Los datos

Del dibujo al código: la tabla es un diccionario

  detector_101.py líneas 7–20
ESTADO_INICIAL = "q0"
ESTADO_ACEPTACION = "q3"

# Función de transición δ: (estado actual, símbolo leído) -> estado siguiente
TRANSICIONES = {
    ("q0", "0"): "q0",  # nada útil todavía
    ("q0", "1"): "q1",  # vimos «1»
    ("q1", "0"): "q2",  # vimos «10»
    ("q1", "1"): "q1",  # «11»: el último 1 puede empezar la secuencia
    ("q2", "0"): "q0",  # «100»: hay que empezar de nuevo
    ("q2", "1"): "q3",  # «101»: ¡encontrada!
    ("q3", "0"): "q3",  # ya la encontramos:
    ("q3", "1"): "q3",  # nada cambia el resultado
}
Dónde empieza (\(q_0\)) y dónde se gana (\(q_3\)).
Un diccionario: la llave es (estado, tarjeta) y el valor, el estado siguiente.
Las tres flechas que avanzan la barra.
Las que se quedan o reinician.
\(q_3\) siempre regresa a \(q_3\).
Cada línea del diccionario es una flecha del diagrama: 8 líneas, 8 flechas. Si alguien cambia una flecha del dibujo, tiene que cambiar exactamente una línea del código.
IV · La solución en Python · La función

La función acepta(cadena), línea por línea

  detector_101.py líneas 23–36
def acepta(cadena):
    """Regresa True si la cadena binaria contiene 101 y False en otro caso.

    Las cadenas con símbolos fuera del alfabeto {0, 1} se rechazan.
    """
    if not isinstance(cadena, str):
        return False
    estado = ESTADO_INICIAL
    for simbolo in cadena:
        siguiente = TRANSICIONES.get((estado, simbolo))
        if siguiente is None:  # símbolo fuera del alfabeto
            return False
        estado = siguiente
    return estado == ESTADO_ACEPTACION
Si no es texto, no es una cadena: False.
Empezamos en \(q_0\).
Tomamos las tarjetas una por una.
Buscamos la flecha en la tabla.
Si no hay flecha, la tarjeta es rara: False.
Nos movemos al estado siguiente.
Al final: ¿estamos en \(q_3\)?
La función regresa siempre un booleano (True o False). La validación del alfabeto sale gratis de la tabla: una pareja (estado, símbolo) que no está en el diccionario significa un símbolo fuera de {0, 1}.

El truco de .get
TRANSICIONES.get((estado, simbolo)) regresa None si esa pareja no existe. Así, cualquier símbolo fuera de {0, 1} se detecta sin escribir otra regla.
«1012» contiene 101, pero el enunciado pide rechazar cualquier cadena con símbolos fuera del alfabeto: el programa se detiene en el «2».

IV · La solución en Python · Sin trampa

¿Y la palabra in que aparece en el código?

Esto sí está

for simbolo in cadena:
Es un ciclo: «para cada tarjeta de la cadena». Recorre los símbolos uno por uno; no busca nada.

Esto no está

"101" in cadena
Esa sería una búsqueda de subcadena: justo lo prohibido. Tampoco hay find, index, count ni expresiones regulares.
El verificador de la presentación revisa detector_101.py y confirma que no contiene "101", find, index, count, re ni __contains__.
La misma palabra de Python (in) tiene dos usos: en un for significa "recorrer"; en una condición significa "¿está adentro?". Solo usamos el primero.
IV · La solución en Python · Para ver el camino

Una función extra: recorrido(cadena)

  detector_101.py líneas 39–47
def recorrido(cadena):
    """Lista de estados visitados, o None si aparece un símbolo inválido."""
    estados = [ESTADO_INICIAL]
    for simbolo in cadena:
        siguiente = TRANSICIONES.get((estados[-1], simbolo))
        if siguiente is None:
            return None
        estados.append(siguiente)
    return estados
Deja huellas
Hace lo mismo que acepta, pero anota cada estado visitado en una lista. Sirve para explicar y para probar.
recorrido("1001")
→ ['q0', 'q1', 'q2', 'q0', 'q1']
estados[-1] es el último estado de la lista, es decir, el estado actual. El resultado coincide con la simulación de la diapositiva 11.

    def test_todas_las_cadenas_hasta_longitud_12(self):
        revisadas = 0
        for n in range(13):
            for simbolos in itertools.product("01", repeat=n):
                cadena = "".join(simbolos)

V · Errores frecuentes

Errores frecuentes al diseñar este autómata

«11» regresa a \(q_0\)

Falla con 1101: el segundo 1 sí podía empezar 101. Corrección: \(q_1\xrightarrow{1}q_1\).

«100» va a \(q_1\)

Acepta 10001, que no contiene 101. Corrección: \(q_2\xrightarrow{0}q_0\).

\(q_3\) no se queda

Rechaza 1010: después de 101 «olvida» que ganó. Corrección: \(q_3\xrightarrow{0,1}q_3\).
Por eso la prueba exhaustiva es tan útil: cada uno de estos errores falla en alguna de las 8191 cadenas.
Cada contraejemplo lo verifica el motor de autómatas de la presentación con los diagramas incorrectos dibujados aquí.
