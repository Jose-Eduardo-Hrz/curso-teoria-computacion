cuando una función se llama a sí misma

Aprende programación descubriendo un truco que se repite una y otra vez.

Bienvenida. Hoy vamos a descubrir un truco de programación que parece magia: una función que, para resolver un problema, se pide ayuda a sí misma. La ruta será siempre la misma: primero una historia, luego un dibujo, después las matemáticas y al final el código.

Intuición · La idea

¿Qué es la recursividad?

En palabras sencillas
La recursividad ocurre cuando una función resuelve un problema llamándose a sí misma para resolver una versión más pequeña del mismo problema.
Tenemos un problema.
Lo hacemos más pequeño.
Resolvemos la parte pequeña de la misma manera.
Llegamos a un problema tan sencillo que ya sabemos resolverlo.
El problema se hace más pequeño hasta que podemos resolverlo directamente.
Relaciona con las cajas: abrir una caja (hacer el problema más pequeño), repetir con la caja de adentro (resolver igual), y el regalo es el problema que ya sabemos resolver. Insiste en "versión más pequeña DEL MISMO problema".
Dibujo · Los dos ingredientes

Los dos ingredientes mágicos

Caso recursivo
La función vuelve a llamarse a sí misma con un problema más pequeño: baja un escalón.
Caso base
El momento en que dejamos de repetir porque ya sabemos la respuesta: el último escalón.
No basta con llamarse a sí misma: la función necesita una condición de terminación y cada llamada debe acercarse a ella.
Vuelve a las cajas: "abrir la caja de adentro" es el caso recursivo; "encontré el regalo, ya no abro más" es el caso base. Si la escalera no tuviera último escalón, bajaríamos para siempre.

Pide a un alumno que sea "la función": cuando recibe el 5, dice "5" y le pasa la tarjeta con el 4 a otro alumno, que hace exactamente lo mismo. Cuando alguien recibe −1, solo dice "terminé". Así se ve que cada llamada es una copia de la misma regla con un número menor.

0Llamamos a la función con 3. Avanza para ver cada llamada.
Bajada: cada llamada muestra su número y llama a la función con uno menos. Las anteriores esperan.
Con -1 se cumple n < 0: caso base. Ya no hay más llamadas.
Regreso: cada llamada termina y el programa vuelve a la anterior. Aquí no queda nada pendiente: esta función solo hace acciones, no devuelve un número.
Señala la sangría: cada llamada está "dentro" de la anterior, como las cajas. En el regreso, las llamadas terminan de abajo hacia arriba (primero la última que empezó). Aclara que no todas las funciones recursivas devuelven un número: esta solo muestra texto. En el factorial veremos que el regreso sí trae resultados.

El primer elemento hace el papel de caso base: sin él, la regla no podría empezar. Pregunta: si cambiamos a_0 = 5, ¿qué sucesión obtenemos? (5, 6, 7, ...). La regla sola no basta: hace falta el punto de partida.
Matemáticas · El factorial

¿De cuántas maneras podemos ordenar 3 objetos?

3 opciones para el primero × 2 para el segundo × 1 para el último \(= 6\)
Factorial de un número
\(n! = n\,(n-1)\,(n-2)\cdots 2\cdot 1\)
La misma idea, de forma recursiva
\(0! = 1\)
caso base
\(n! = n\cdot(n-1)!,\quad n\geq 1\)
caso recursivo
¿Por qué \(0! = 1\)? Es una convención fundamental: hace que \(1! = 1\cdot 0! = 1\) funcione, y hay exactamente una manera de ordenar cero objetos (no hacer nada). Sin este caso base, la regla nunca se detendría.
No pidas memorizar: haz que vean que "ordenar n objetos" = elegir el primero (n formas) y luego ordenar los n−1 restantes, que es el MISMO problema más pequeño. Eso es exactamente n! = n·(n−1)!.
Matemáticas · Bajada y regreso

Calculemos \(4!\) paso a paso

Bajada · queda pendiente
Regreso · se completa
\(4! = 4\cdot 3!\) pendiente
←
\(4! = 4\cdot 6 = \mathbf{24}\) resultado
\(3! = 3\cdot 2!\) pendiente
←
\(3! = 3\cdot 2 = 6\) regresa 6
\(2! = 2\cdot 1!\) pendiente
←
\(2! = 2\cdot 1 = 2\) regresa 2
\(1! = 1\cdot 0!\) pendiente
←
\(1! = 1\cdot 1 = 1\) regresa 1
\(0! = 1\) caso base
↗
valor conocido: \(1\) regresa 1
Al bajar, cada cuenta queda a medias (borde punteado, reloj de arena). Al llegar al caso base, los resultados suben uno por uno y completan las cuentas pendientes.
Lee la columna izquierda de arriba abajo (bajada) y la derecha de abajo hacia arriba (regreso). Pregunta antes de cada clic del regreso: ¿cuánto vale 2!? Así participan. Las formas (punteado vs. sólido) y los íconos distinguen los dos momentos, no solo el color.
Código · JavaScript

Del papel al código

  factorial.js
function factorial(n) {
    if (n < 0) {
        throw new Error("El número debe ser no negativo");
    }

    if (n === 0) {
        return 1;
    }

    return n * factorial(n - 1);
}

console.log(factorial(4)); // 24
Recibe un número n.
Comprueba que la entrada sea válida: si es negativa, error.
caso base si n es 0, devuelve 1.
caso recursivo se llama a sí misma con n - 1.
Cuando la llamada retorna, multiplica n por ese resultado.
Probamos: factorial(4) muestra 24.
Este ejemplo supone enteros no negativos. Un programa real puede necesitar más validaciones (por ejemplo, rechazar 2.5 con Number.isInteger) y cuidar números muy grandes.
Compara con la diapositiva anterior: if (n === 0) return 1 es 0! = 1, y return n * factorial(n - 1) es n! = n·(n−1)!. El código es casi una traducción literal de la definición matemática. ¿Qué pasaría con factorial(2.5)? 2.5, 1.5, 0.5, −0.5 → error: nunca llega exactamente a 0.
Dibujo · La pila de llamadas

¿Cómo recuerda el programa lo que tiene pendiente?

factorial(4) 4 × ?4 × 6 = 24
factorial(3) 3 × ?3 × 2 = 6
factorial(2) 2 × ?2 × 1 = 2
factorial(1) 1 × ?1 × 1 = 1
factorial(0) caso base: 1
pila de llamadas
Imagina una pila de platos. Cada vez que empezamos una tarea nueva, ponemos un plato encima. Cuando terminamos, retiramos el de arriba.
Cada llamada guarda sus propios datos
su valor de n y lo que le falta por hacer
Y recuerda a dónde regresar
el punto exacto donde se quedó la anterior
0La pila empieza vacía. Llamamos a factorial(4).
Crece: cada llamada pone un plato nuevo arriba y deja su cuenta pendiente (⌛).
factorial(0) es el caso base: ya sabe que vale 1. ¡No pone más platos!
Se reduce: se quita el plato de arriba y su resultado completa la cuenta del plato de abajo.
La pila queda vacía y el resultado final es 24.
Diez clics: cinco para apilar y cinco para desapilar. El último plato que se puso es el primero que se quita (LIFO). Si la pila crece demasiado (miles de platos), el programa se queda sin espacio: eso veremos al olvidar el caso base.

Errores comunes · Sin caso base

¿Qué ocurre si olvidamos el caso base?

  contar.js · incorrecto
function contar(n) {
    console.log(n);
    return contar(n - 1);
}
nunca se detiene por sí sola
simulación controlada · profundidad 0
Pulsa «Simular contar(5)».
pila
  contar.js · corregido
function contar(n) {
    if (n < 0) return;   // caso base
    console.log(n);
    contar(n - 1);       // más pequeño
}
se detiene al llegar a n < 0
Sin caso base, cada llamada pone otro plato en la pila… hasta que no cabe ninguno más: RangeError: Maximum call stack size exceeded (desbordamiento de pila).
También falla si la llamada no se acerca al caso base, por ejemplo contar(n + 1) o contar(n).
La simulación NO ejecuta el código infinito: es una animación que imita lo que pasaría, y se detiene con el mensaje de error que mostraría el navegador. El límite real depende del navegador (en Chrome, alrededor de diez mil llamadas para una función sencilla).
Código · Comparación

Recursividad frente a iteración

  recursiva
function contarRecursivo(n) {
    if (n === 0) return;
    console.log(n);
    contarRecursivo(n - 1);
}
  iterativa
function contarIterativo(n) {
    for (let i = n; i > 0; i--) {
        console.log(i);
    }
}
Aspecto Recursiva Iterativa
Cómo repiteLa función se llama a sí mismaUn ciclo (for, while) vuelve a empezar
EstructuraCaso base + caso recursivoVariable de control + condición del ciclo
Cómo terminaAl llegar al caso baseCuando la condición del ciclo es falsa
VentajasNatural para datos anidados (árboles, carpetas)Suele ser más rápida y sencilla de seguir
DesventajasRiesgo de desbordar la pilaCon datos anidados el código se complica
MemoriaUn «plato» por llamada activa (crece con n)Constante: solo unas variables
La recursividad puede hacer algunas soluciones más naturales, pero no siempre es más rápida ni gasta menos memoria: la iteración evita mantener muchas llamadas activas.
Ambas funciones imprimen 3, 2, 1. Todo lo que se hace con recursión se puede hacer con iteración (a veces con una pila explícita) y viceversa. La pregunta no es cuál es "mejor" sino cuál expresa más claramente el problema.

  contarArchivos.js
function contarArchivos(carpeta) {
    let total = 0;
    for (const cosa of carpeta.contenido) {
        if (cosa.esArchivo) total = total + 1;     // caso base
        else total = total + contarArchivos(cosa); // subcarpeta

Sumar los números de 1 a \(n\)

caso recursivo
\(S(4) = 4 + S(3)\)

Cada paso quita una columna: el problema se hace más pequeño.
  suma.js
function suma(n) {
    if (n === 0) return 0;      // caso base
    return n + suma(n - 1);     // caso recursivo
}

console.log(suma(4)); // 10
Mismo esquema que el factorial, cambiando × por + y el caso base 1 por 0. ¿Por qué S(0) = 0 y no 1? Porque sumar "nada" da 0 (el neutro de la suma), igual que multiplicar "nada" da 1 (el neutro del producto). Dato extra: S(n) = n(n+1)/2, la fórmula de Gauss.
